# R3: iteration 20 전후 성능 변화 분석

분석일: 2026-09-08. 대상: `rl/runs/r3/log.jsonl`, 관련 학습·탐색·평가 코드, 저장된 체크포인트. 학습 코드를 수정하거나 재학습하지 않았으며, 아래 추가 실험은 기존 가중치로 수행한 추론·대국이다.

## 요약 판단

**greedy 상대 성능 하락은 실제로 재현된다. 하지만 전체 실력이 일괄적으로 무너졌다고 보기는 어렵다. 후기 모델(iter29)이 이전 모델(iter20)과의 직접 대결에서는 41승 23패를 기록했다.**

현재 증거에 가장 잘 맞는 설명은 **자기대국을 따라 정책과 방문 국면이 바뀌면서, 이전 모델에 대응하는 능력과 기존 평가 상대에 대응하는 능력이 엇갈린 것**이다. 즉 상대에 따라 성능 변화의 방향이 다르다. 과거 대응력의 망각, 상대 분포 편향, 불안정한 정책 개선이 가능한 원인이다. 다만 이것들을 구분하는 재학습 대조 실험은 하지 않았으므로, 특정 하나를 확정 원인이라고 부를 수는 없다.

신경망/배치 크기의 한계, AlphaZero 자체의 한계, 게임 통달, 단순 평가 잡음만으로 이 결과를 설명할 근거는 부족하다. 특히 게임 통달을 뒷받침하는 증거는 없다. 이후 회복은 가능하지만 이 로그는 iteration29에서 끝나므로 예측할 수 없다.

## 1. 로그가 말하는 것과 말하지 않는 것

전체 30행(iter0–29), 자기대국 18,000판, optimizer update 19,574회다. 평가가 기록된 시점은 **9, 19, 29뿐**이다. 따라서 로그만으로 “정확히20부터 하락했다”고 특정할 수 없다.

| 지표 | iter9 | iter19 | iter29 |
|---|---:|---:|---:|
| greedy 상대 점수, 각500판 | 93.6% | 88.2% | 61.8% |
| greedy 상대 흑 | 94.0% | 87.6% | 55.6% |
| greedy 상대 백 | 93.2% | 88.8% | 68.0% |
| random 상대 점수, 각128판 | 100% | 100% | 94.5% |
| 작은 패널로 산출한 Elo | 미기록 | 852 | 742 |
| policy loss | 1.7661 | 1.5660 | 1.5722 |
| value loss | 0.8948 | 0.9103 | 0.8920 |

iter19→29의 greedy 하락은 **26.4%p**다. 각 대국을 독립적인 이항 시행으로 근사하면 하락폭의 95% 구간은 약21.3–31.5%p다. 정확한 분포/독립성 가정을 검증한 것은 아니지만, 이 크기의 차이를 단순 표본 잡음이라고 치부하는 것은 타당하지 않다. 아래 재대국에서도 같은 방향이 확인됐다.

반면 Elo 패널은 상대당 흑15판+백15판뿐이다. 이 작은 패널의 변동성과 별도의500판 greedy 평가의 변동성을 혼동하면 안 된다. iter14 상대 점수는60.0%→63.3%였으므로 원래 패널 자체에서도 모든 상대에 대한 동시 하락은 아니었다.

동일 모델의 자기대국에서 흑백 승률이50% 부근이라는 사실만으로 강함이나 수렴을 판단할 수 없다. 선후수 규칙이 비대칭이므로 같은 모델이라고 반드시50%가 되는 것도 아니다. policy loss의 최저점은iter22의1.5268이며, 이동하는 자기대국 표적을 잘 맞추는 것과 외부 상대에게 이기는 것은 다른 문제다.

## 2. 같은 조건으로 실제 대국을 다시 돌린 결과

체크포인트20과29에 동일한 현재 게임 엔진·평가 코드·상대·기본 시드를 사용했다. 흑백 판수는 동일하다. 점수는 승리1, 무승부0.5이며 직접 대결에는 무승부가 없었다. 서로 다른 실험 행은 조건이 다르므로 **행 안에서 두 모델을 비교**해야 한다.

| 실험 | 판수/모델 | iter20 | iter29 |
|---|---:|---:|---:|
| CPU, Gumbel32, greedy | 96 | 84.4% | 63.5% |
| MPS, Gumbel32, greedy | 64 | 87.5% | 60.9% |
| MPS, Gumbel128, greedy | 64 | 84.4% | 57.8% |
| 탐색 없이 정책 argmax, greedy | 256 | 89.1% | 57.0% |
| 첫7번 착수를 무작위화한 뒤 정책 argmax, greedy | 256 | 87.9% | 69.9% |

CPU Gumbel32의 Wilson95% 구간은 iter20 약75.8–90.3%, iter29 약53.6–72.5%다. 기본 시드는 같지만 정책에 따라 진행 경로와 난수 소비가 달라지므로 동일 국면을 짝지은 실험은 아니다. 신뢰구간은 대국 점수를 이항으로 근사한 보조 지표다.

**추가로 두 모델끼리 붙이면 iter29가64판 중41판 승리(64.1%)했다.** iter29가 흑일 때20승12패, 백일 때21승11패다. 95% Wilson 구간은 대략51.8–74.7%다. 64판이라 정밀한 서열 확정은 아니지만, greedy 하락을 곧바로 모든 상대에 대한 실력 하락으로 번역할 수 없다는 중요한 반대 증거다. 이 결과만으로 비추이적 순환 관계가 증명된 것도 아니다.

탐색 없는 정책에서도 greedy 대응력이 떨어졌으므로 문제를 마지막 탐색 단계의 선택 잡음만으로 설명할 수 없다. iter29 정책-only는 기본 오프닝에서 흑26.6%/백87.5%로 크게 갈렸고, 첫7수 무작위화 후에는 흑66.4%/백73.4%가 되었다. 기본 초반 진행에서 드러나는 취약성이 일부 커진 것이다. 그래도 전체 약18.0%p 격차가 남아, 단 하나의 고정 오프닝만의 문제로 전체 하락을 설명할 수 없다.

**추론시 탐색량을32→128로 늘려도 회복이 관측되지 않았다.** 같은 MPS·시드·판수에서 iter29는60.9%→57.8%였다. 64판씩이라 이3.1%p 차이로 탐색 증가가 해롭다고 할 수는 없다. 그러나 “그냥 추론 탐색을 늘리면 후기 모델의 성능이 돌아온다”는 설명은 이번 실험에서 지지되지 않았다. 더 많은 탐색으로 재학습했을 때의 효과는 별도 문제다.

추가 대국은 모두 합해1,536판이다. 결과 파일: [CPU32](matches-32-20-29.json), [MPS32](matches-mps-32-32-20-29.json), [MPS128](matches-128-20-29.json), [정책만](policy-only.json), [무작위 오프닝](random-openings-policy.json), [직접 대결](head-to-head.json).

## 3. 원인 후보의 우선순위

아래 순서는 증거가 뒷받침하는 설명의 수준과 후속 검증 우선순위다. 각 요인이 하락에 얼마나 기여했는지 측정한 인과적 순위는 아니다.

### 가장 잘 뒷받침되는 현상: 상대별 성능 변화와 자기대국 분포 이동

학습은 최신 모델끼리 만든 자기대국을 사용한다. replay는 최근300,000개 국면을 보존하고 한 iteration마다 약42,000개가 들어오므로 대략7 iterations의 이동 창이다. 오래된 모델/다양한 상대에 대한 평가 성능을 보존하도록 직접 최적화하는 구조는 아니다.

동일128개 국면에서 iter20과29의 정책 argmax가 **50%** 달랐다. 최근 replay의 동일4,096개 국면에서는 후기 모델이 정책 표적과 결과를 더 잘 맞췄다.

| 최근 replay에 대한 적합도 | iter20 | iter29 |
|---|---:|---:|
| policy cross entropy | 1.8792 | 1.5752 |
| value MSE | 0.9245 | 0.9012 |
| value 부호 정확도 | 58.0% | 60.0% |

**이것은 held-out 검증이 아니다.** 후기 모델이 학습에 사용한 최근 데이터여서 후기 모델에 유리하다. 따라서 일반화 향상의 증거로 쓸 수는 없다. 다만 최근 자기대국 데이터 적합도는 올라가는데 greedy 대응력은 떨어지고 직접 대결 결과는 반대라는 관측이 함께 나온다. 단순 학습 중단/전체 붕괴보다는 학습 대상과 평가 상대의 불일치, 전략 변화·망각 가능성과 일치한다.

근거 코드: `rl/train.py:46` 최신 모델 자기대국, `rl/train.py:66` FIFO replay, `rl/train.py:166` 데이터 생성·학습 루프.

### 기여할 수 있는 구조: 짧은 탐색과 아직 부정확한 value

현재 설정은64채널·6 residual blocks·9입력 planes, batch512, `sims=32`, 후보`m=16`이다. 이 게임은 첫 턴 이후 한 사람이 두 번 연속 착수한다. 한 번 착수하는 게임보다 같은 탐색 깊이에서 상대의 대응까지 읽기가 어렵다.

16개 후보가 있는 경우 현재 스케줄은 `16×1 + 8×1 + 4×2 + 2×4 = 40`회다. 이름은32 sims지만 정수 배분의 최소1회 때문에 실제로40회가 된다. 후보 절반은 첫 평가 한 번 뒤에 제거된다. 이는 자원 배분 특성이지, 자체로 하락 원인이 입증된 버그는 아니다.

동일128개 국면에서 **탐색 종료 후 트리 말단들의 평균 깊이**는 iter20/29 모두 **약2.38번 착수**였다. 모든 simulation의 방문 횟수로 가중한 평균 깊이는 아니며, 모든 가지가 그 깊이에 그친다는 뜻도 아니다. 128 sims에서는 각각4.15/4.07로 깊어졌다. 양 모델의32 sims 깊이가 비슷하고128 sims 재평가도 성능을 회복시키지 못했으므로, 얕다는 사실만으로20 이후 하락을 설명할 수는 없다.

별도 최근 replay4,096개를 단계별로 보면 점유4–23칸의 초반에서 iter29 value 부호 정확도는50.6%, MSE는1.003이었다. 반면64–83칸에서는77.0%,0.593이었다. 학습 데이터에서도 초반 승패 신호가 약하고 후반에 더 좋아진다. 이런 value에 짧은 탐색을 붙이면 틀린 개선 표적을 자기대국으로 되먹일 가능성이 있다. 다만 초반 승패의 본질적인 불확실성도 있어서 이 수치만으로 value 구현 오류나 용량 부족을 판정할 수 없다.

원자료: [같은 국면 탐색 비교](probe-results.json), [단계별 value](value-by-phase.json). 코드: `rl/mcts.py:20`, `rl/mcts.py:114`.

### 별도로 관리할 위험: 고정 학습률과 불완전한 resume

학습률은0.002로 고정되어 있고 decay가 없다. resume에서는 신경망 가중치만 읽고 **AdamW를 새로 만든다**. 체크포인트에는 optimizer moment와 RNG 상태가 저장되지 않는다. replay 용량은300,000인데 저장량은200,000이다.

실제 실행 기록에서도 iter15와iter19 재시작 때200,000개만 복원했다. 따라서 연속 학습과 동일한 resume가 아니며, optimizer 상태 리셋과 과거 데이터 일부 소실이 동시에 일어났다.

이는 실제 확인된 학습 안정성 위험이다. 하지만 iter20은 재시작 뒤에도 greedy 대응력이 좋았고, 고정 학습률을 바꾼 대조 실험도 하지 않았다. 따라서 **“0.002가 너무 크다” 또는 “resume가 이번 하락의 주원인이다”는 아직 가설**이다.

## 4. 신경망 붕괴 또는 구현 오류인가?

동일 국면에서 다음과 같았다.

| 지표 | iter20 | iter29 |
|---|---:|---:|
| 정책 entropy | 1.465 | 1.486 |
| 최대 행동 확률 평균 | 0.467 | 0.455 |
| value 표준편차 | 0.396 | 0.411 |
| 탐색 표적과 정책의 KL | 0.734 | 0.772 |

정책이 갑자기 한 수로 집중되거나 value가 상수로 붕괴했다는 모습은 아니다. 탐색 표적도 원래 정책과 계속 다르다. 다만 **KL이 크다는 것은 변화가 있다는 뜻이지, 그 변화가 올바르다는 뜻은 아니다.**

소스 검토에서 같은 플레이어의 연속 착수에 대한 value 부호 처리는 플레이어가 실제로 달라질 때만 뒤집도록 되어 있었다. Gumbel의 `c_visit=50`, `c_scale=1`은 원 논문의 예시와 맞아서 이 상수만을 버그로 볼 수 없다. 검토 범위에서 하락을 설명하는 확정적인 부호/표적 버그는 찾지 못했다. 이는 전체 코드에 오류가 없다는 증명은 아니다.

batch512와64×6 구조는 모든 비교 체크포인트에서 동일하다. 용량 부족이 망각에 기여할 수는 있지만 네트워크 확대·batch 변경의 통제 실험 없이 “구조적 한계에 도달했다”고 결론 내릴 수 없다. 이번 증거에서는 그보다 상대 분포와 평가의 불일치를 먼저 다루는 편이 타당하다.

## 5. 질문한 네 가지 가능성에 대한 답

| 가능성 | 현재 판단 |
|---|---|
| 신경망/배치 크기의 구조적 한계 | 배제할 수 없지만 주원인으로 지목할 증거 부족. 같은 구조의 후기 모델이 이전 모델을 이기기도 함. |
| AlphaZero 자체의 한계 | 이 실험으로 판단 불가. 유한 탐색·근사 value·움직이는 자기대국 분포에서 매 체크포인트의 모든 상대 승률이 단조 증가하는 것은 보장되지 않음. |
| 게임에 통달함 | 뒷받침되지 않음. greedy 및 random에게 패하며, 후속 모델/탐색 예산에 따른 행동 변화도 큼. 엔진의 안전 수 필터도 도움을 주므로 높은 random 승률만으로 숙련을 평가할 수 없음. |
| 일시적 하락이며 이후 상승 가능 | 회복 가능성은 열려 있음. 그러나 지금 하락은 재현되며, iter30 이후 자료가 없어 자연 회복을 장담할 수 없음. |

Gumbel AlphaZero의 정책 개선 논의는 정확한 action value 평가 등의 전제에 의존한다. 근사 critic과 신경망 학습을 포함한 실제 파이프라인의 외부 승률이 매번 올라간다는 보장은 아니다. [원 논문, Danihelka et al., ICLR2022](https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/gumbel-alphazero.pdf).

원래 AlphaZero도 최신 신경망을 계속 업데이트하는 자기대국 체계이며, 문헌의 큰 탐색량이나 batch 크기는 이 게임에 대한 필요조건 또는 최적값을 뜻하지 않는다. 따라서 “원 논문보다 작으니 알고리즘의 한계”라는 비교는 성립하지 않는다. [AlphaZero 논문, Silver et al.](https://storage.googleapis.com/deepmind-media/DeepMind.com/Blog/alphazero-shedding-new-light-on-chess-shogi-and-go/alphazero_preprint.pdf).

## 6. 다음에 원인을 분리한다면

아래는 제안이며 이번 분석에서 재학습은 실행하지 않았다.

1. **평가 기준부터 고정한다.** greedy뿐 아니라 여러 과거 체크포인트, 무작위 오프닝, 흑백 균형, 충분한 판수로 상대별 점수를 보존한다. 단일 Elo나 최신 체크포인트 하나만으로 전체 실력/최고 모델을 결정하지 않는다.
2. **같은 시작점에서 학습률만 비교한다.** 예:0.002와0.0002. optimizer/replay/RNG 복원 조건은 두 실험에서 같게 하고, 앞으로는 전체 상태를 보존한다. 지금 파일에는 과거 Adam 상태가 없으므로 그 상태의 정확한 연속 재현은 불가능하다.
3. **그다음 탐색 예산과 상대/데이터 다양성을 각각 분리한다.** 학습시32 vs128 sims, 고정 예산에서 후보16 vs8, 과거 정책과 대국하는 방식/과거 데이터 보존을 개별 실험한다. 여러 항목을 동시에 바꾸면 원인을 구분할 수 없다.
4. **네트워크와 batch 확대는 그 뒤에 비교한다.** 동일 평가·데이터·연산량 기준을 정해 용량과 최적화 효과를 분리한다. batch를 바꾸면 현재 코드의 iteration당 optimizer step 수도 바뀌므로 별도 통제가 필요하다.

현재 가장 합리적인 결론은 **“더 이상 배울 것이 없다”가 아니라 “무엇에 강해지는지를 한 개의 승률로 표현하기 어려워졌고, 현재 자기대국 루프가 일부 기존 대응력을 보존하지 못하고 있다”**이다. 전략 이동의 근본 원인이 학습률인지, 탐색 표적의 질인지, 용량인지까지 확정하려면 위 대조 실험이 필요하다.
